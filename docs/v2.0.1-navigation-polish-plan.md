# v2.0.1 Navigation Polish Plan

**Branch:** `planning/v2.0.1-navigation-polish`  
**Target:** v2.0.1 stabilization release  
**Scope:** Frontend navigation, wording, and cross-linking polish only

---

## Goal

Make Munmai feel like a set of connected financial workflows rather than a list of independent features. Users should be able to move naturally between related pages without having to remember where things live in the sidebar.

---

## Why This Release Exists

Munmai v2.0.0 shipped a complete feature set: income, expenses, receipts, imports, groups, debt, reports, and trust pages. All features are functional and demo-ready.

However, a UX/navigation audit revealed that the app currently reads like a feature checklist. Related workflows are scattered across different sidebar sections, some items are misnamed or misordered, and there are few visual cues guiding users between connected pages.

v2.0.1 is a focused polish pass to improve navigation clarity, cross-linking, and demo experience without adding new features or changing routes.

---

## Current Navigation Problems

1. **Sidebar "Receipts" label is ambiguous.** Users expect this to mean "receipts attached to expenses," but it actually links to the standalone Receipt Inbox prototype.
2. **Reports section ordering is backwards.** Tax Pack appears before Monthly Summary, but Monthly Summary is the more frequently used report.
3. **Financial Life section ordering is backwards.** Opening Balance appears before Debt Reality, but Debt Reality is the more actively used feature.
4. **Global Shared Expenses and Settlements items are confusing.** These are group-scoped features, but they appear as top-level sidebar items, implying they work outside of groups.
5. **Dashboard lacks quick actions.** Users land on Dashboard but have no obvious way to jump to high-value workflows like Receipt Inbox, Import Statements, or Monthly Summary.
6. **No cross-links between related pages.** Receipt Inbox, Transactions, Import Statements, and reports are isolated. Users must return to the sidebar to navigate between them.
7. **Settings wording is outdated.** Still references "receipt coverage" language instead of Receipt Inbox and document management.

---

## Recommended v2.0.1 Scope

### 1. Rename sidebar "Receipts" to "Receipt Inbox"
- **File:** `client/src/components/Sidebar.jsx`
- **Change:** Update label from "Receipts" to "Receipt Inbox"
- **Why:** Clarifies that this is the standalone receipt document management feature, not expense-linked receipts

### 2. Reorder Reports section
- **File:** `client/src/components/Sidebar.jsx`
- **Change:** Move Monthly Summary above Tax Pack
- **Why:** Monthly Summary is the primary report; Tax Pack is a specialized export tool

### 3. Reorder Financial Life section
- **File:** `client/src/components/Sidebar.jsx`
- **Change:** Move Debt Reality above Opening Balance
- **Why:** Debt Reality is actively used for tracking liabilities; Opening Balance is a one-time setup

### 4. Remove or clarify global Shared Expenses and Settlements items
- **File:** `client/src/components/Sidebar.jsx`
- **Change:** Either remove these from the top-level sidebar or add a note that they are group-scoped
- **Why:** These features only work within groups. Displaying them globally implies standalone functionality.
- **Decision needed:** Remove entirely, or keep with "(in groups)" suffix?

### 5. Add Dashboard quick actions
- **File:** `client/src/pages/Dashboard.jsx`
- **Change:** Add a quick actions card or section with links to:
  - Receipt Inbox
  - Import Statements
  - Monthly Summary
  - Debt Reality
- **Why:** Dashboard is the landing page. Users should have obvious entry points to high-value workflows.

### 6. Add "Related actions" cross-links
- **Files:** Multiple page components
- **Change:** Add a small "Related actions" section or footer links between:
  - Receipt Inbox ↔ Transactions
  - Import Statements ↔ Monthly Summary
  - Monthly Summary ↔ Tax Pack
  - Debt Reality ↔ Opening Balance
- **Why:** Guides users between connected workflows without requiring them to return to the sidebar

### 7. Update Settings wording
- **File:** `client/src/pages/Settings.jsx`
- **Change:** Replace "receipt coverage" language with Receipt Inbox and document management wording
- **Why:** Settings should reflect the current feature set, not legacy terminology

## Out of Scope

The following are **explicitly not part of v2.0.1**:

- OCR receipt extraction
- AI receipt parsing
- Receipt-to-expense linking
- Subscriptions/billing
- Utility Tools (PDF compression, JPG-to-PDF)
- Bank sync
- Mobile app
- Full tax filing engine
- Full navigation redesign
- Command palette
- Onboarding tour

These are planned for future releases but are not part of this polish pass.
