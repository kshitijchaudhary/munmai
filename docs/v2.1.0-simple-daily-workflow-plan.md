# Munmai v2.1.0 - Simple Daily Workflow Plan

## Product Reality Check

Munmai currently has many useful systems: transactions, receipts, imports, reports, groups, debt tracking, opening balance, and tax-pack foundations.

The problem is not capability. The problem is visibility and effort.

Too many systems are visible at once. The app can feel like an admin-heavy finance console instead of a tool someone uses when they are tired, busy, or just trying to quickly record what happened today.

Most users do not want to spend 5-10 minutes organizing money. They want to capture the important thing, understand whether they are okay this month, and move on.

A finance app should reduce headache, not create homework. Munmai needs to shift from feature-heavy to daily-use friendly.

## v2.1.0 Goal

Make Munmai simple enough that the creator would personally use it.

Munmai should be usable in 30-60 seconds per session. The product should prioritize fast capture, simple review, and clear monthly understanding.

Advanced workflows should stay available, but they should not dominate the first experience or the daily workflow.

## New Product Rule

Before adding or showing any feature, ask:

- Does this reduce user headache?
- Can a tired user understand this in 5 seconds?
- Can the main action be completed in 30 seconds?
- Is this daily-use, weekly-review, or occasional-use?

If a feature is not daily-use, it should not compete with daily-use actions for attention.

## Primary User Workflows

### A. Daily Money

- Add income
- Add expense
- Upload receipt
- See this month quickly

Daily workflows should be visible first. These are the actions users need when they open Munmai for a short session.

### B. Review

- Review imported statement rows
- Review receipts missing details
- Check Monthly Summary
- Clean up records only when needed

Review workflows should be visible second. They matter, but they are not always urgent in the moment.

### C. Occasional / Life

- Groups
- Debt Reality
- Tax Pack
- Opening Balance
- Settings

Occasional workflows should not dominate the UI. They should be easy to find when needed, but they should not make daily usage feel heavy.

## Proposed Sidebar / Navigation Concept

One simplified navigation concept:

- Dashboard
- Money
- Receipts
- Reports
- More

`More` can contain:

- Imports
- Groups
- Debt
- Tax Pack
- Opening Balance
- Settings

An alternative slightly more explicit version:

Main:

- Dashboard
- Transactions
- Receipts

Reports:

- Monthly Summary

More:

- Imports
- Groups
- Debt Reality
- Tax Pack
- Settings

The final navigation should be chosen after reviewing actual screens, not only from a list. The right structure is the one that makes the daily path obvious while keeping advanced modules reachable.

## Dashboard Concept

Dashboard should become the main command center.

It should focus on:

- Add Transaction
- Upload Receipt
- Import Statement
- This month In / Out / Net
- Recent activity
- Needs review
- Quick insight

Dashboard should avoid showing too many modules at once. The first question it should answer is: "What should I do right now?"

## Form Simplification Concept

All major forms should use progressive disclosure.

Default transaction form:

- Type
- Amount
- Vendor / Source
- Save

Optional details:

- Date
- Category
- Tax Pack
- Receipt
- Notes

Receipt upload default:

- File
- Upload

Optional details:

- Vendor
- Amount
- Date
- Category
- Tags
- Notes

Group actions should also stay simple and modal-based:

- Add expense
- Settle up
- Invite

The default form should capture the minimum useful record. Organizing can happen later.

## Screen-Level Problems To Fix Later

- Dashboard feels like many feature cards instead of one clear daily command center.
- Transactions still feels data-table heavy.
- Receipt Inbox improved but still needs simpler "save now, organize later" thinking.
- Groups still needs stronger Splitwise-like emotional clarity: who owes whom, recent activity, settle up.
- Tax Pack should not feel like a main daily feature.
- Opening Balance should be setup-only, not a frequent navigation item.
- Advanced import workflows should not dominate daily use.

## v2.1.0 Recommended Scope

v2.1.0 should be planning plus selective UI simplification, not a full redesign.

Recommended scope:

- Redesign Dashboard information hierarchy.
- Simplify navigation groups.
- Simplify Add Transaction modal using progressive disclosure.
- Make Upload Receipt even more file-first if needed.
- Add "Needs review" surfaces for missing receipt details and import cleanup.
- Reduce sidebar and page clutter.
- Improve copy so users know what to do next.

## Out of Scope

- New backend features
- Bank sync
- OCR
- AI parsing
- Subscription billing
- Mobile app
- Full tax filing
- Income document attachments
- Utility tools
- New group calculation logic
- Full visual redesign from scratch

## Success Criteria

Munmai v2.1.0 should be considered successful if:

- The creator can use it daily without feeling annoyed.
- A new user understands the Dashboard in 5 seconds.
- Adding a transaction takes under 30 seconds.
- Uploading a receipt takes under 30 seconds.
- Advanced workflows are still available but not overwhelming.
- The app feels like a money companion, not a data-entry dashboard.

## Implementation Phases

### Phase 1: Product / Navigation Decision

- Review current screens.
- Decide which workflows are daily, review, and occasional.
- Choose the simplest navigation structure that supports those layers.

### Phase 2: Dashboard Simplification

- Make Dashboard the command center.
- Prioritize fast actions, current-month understanding, recent activity, and needs-review signals.
- Remove or demote modules that are not daily-use.

### Phase 3: Add Transaction Progressive Disclosure

- Make the default transaction form minimal.
- Move lower-frequency fields into optional details.
- Keep the transaction capture path under 30 seconds.

### Phase 4: Receipt / Import Review Simplification

- Make receipt capture file-first.
- Keep import review powerful but less dominant in daily navigation.
- Surface only records that need user attention.

### Phase 5: Groups Emotional Clarity Later

- Improve group screens around who owes whom, recent activity, and settle-up.
- Keep the underlying group calculations unchanged unless a later product decision requires deeper work.

## Final Principle

Munmai should not ask users to organize their financial life all at once.

Munmai should help users capture today, review later, and understand the month.
