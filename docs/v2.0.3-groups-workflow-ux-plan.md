# Munmai v2.0.3 Groups Workflow UX Plan

## Goal

Polish the Groups workflow so users have one clear place to manage group collaboration: `/groups`.

The Groups page should act as a Group Hub for creating groups, joining with a code, reviewing invitations, and opening existing groups. Group-scoped work such as shared expenses, balances, settlements, and members should remain inside a selected group.

## Why This Release Exists

Munmai group functionality is already in place, but the current navigation can make group-scoped features look global. Shared expenses and settlements only make sense after a user selects a group, so exposing them as global sidebar links creates wasted clicks and confusion.

v2.0.3 should reduce that friction without changing backend behavior or group business logic.

## Current Problems

- The global sidebar exposes group-scoped concepts:
  - Shared Expenses
  - Settlements
- These sidebar items redirect users toward groups instead of opening a true global shared-expense or settlement page.
- The Groups page currently shows an always-visible Create Group form, which makes the page feel more like an admin screen than a hub.
- Join Group is already modal-based, but Create Group is not.
- Invitations live on a separate route and are accessible from the sidebar, but they belong naturally inside the group workflow.
- Group summary tabs are correctly scoped inside a selected group and should not be removed.

## Recommended v2.0.3 Scope

- Sidebar Groups section should have one global entry:
  - Groups -> `/groups`
- Remove global sidebar links:
  - Invitations
  - Shared Expenses
  - Settlements
- Keep `/group-invitations` route available.
- Add Invitations access from the Groups page.
- Make `/groups` act as a Group Hub.
- Move the always-visible Create Group form into a Create Group modal.
- Keep the existing JoinGroupModal.
- Add top hub actions:
  - Create group
  - Join with code
  - Invitations
- Keep the group list as the primary content.
- Keep Group Summary tabs unchanged:
  - Summary
  - Expenses
  - Balances
  - Settlements
  - Members

## Out Of Scope

- Backend changes.
- Route deletion.
- Deleting `/group-invitations`.
- Changing group permissions.
- Changing shared expense logic.
- Changing settlement logic.
- Changing group balance calculations.
- Creating a global shared expense page.
- Creating a global settlements page.
- Full group redesign.

## Implementation Checklist

1. Update `client/src/components/Sidebar.jsx`.

   - `Groups` -> `/groups`
3. Remove global `Invitations`, `Shared Expenses`, and `Settlements` sidebar items.
4. Remove any now-unused group-scoped sidebar helper logic.
5. Update `client/src/pages/Groups.jsx`.
6. Add a Create Group modal state.
7. Move `GroupForm` from the always-visible inline page layout into a modal.
8. Keep `JoinGroupModal` as the join-code flow.
9. Add top Group Hub actions:
   - Create group
   - Join with code
   - Invitations
10. Add an Invitations CTA/link to `/group-invitations`.
11. Keep the group list as the main page content.
12. Update small copy if needed:
   - “Open a group to manage shared expenses, balances, settlements, and members.”
13. Do not change `GroupSummary.jsx` tab behavior.
14. Run the client build.
